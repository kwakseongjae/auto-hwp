## 3. 조판 계측기 사용법 (이 트랙의 핵심 도구)

```bash
node scripts/oracle-sweep.mjs            # 전수 재실행 → corpus/typeset-oracle.json 갱신
node scripts/oracle-sweep.mjs --check    # 회귀 검사(로컬)
node scripts/tag-corpus.mjs              # 요소 태깅 재생성(코퍼스 변경 시)
node scripts/fetch-gov-corpus.mjs        # GOV 벤치 재현(바이너리는 커밋하지 않는다)
```

산출물: `corpus/typeset-oracle.json`(문서별 점수) · `corpus/TYPESET-COVERAGE.md`(요소 태깅) ·
`corpus/TYPESET-ORACLE.md`(요약).

### 점수를 읽는 규율 — 어기면 계측이 죽는다

- 점수는 **한/글의 참값이 아니라 저장 `<hp:lineseg>` 기준의 회귀 잠금**이다. 문서·출력에 이 문구를 유지하라.
- **"채점 불가"와 "0점"을 섞지 마라.** 변환 HWPX는 `linesegarray`가 비어 대조 자체가 성립하지 않는다.
  현재 채점 불가 3건(`프로젝트 계획서.hwpx`·`SimpleEquation.hwpx`·`corpus/sample.hwpx`)은 점수가 `null`이다.
- ⚠️ **오라클을 느슨하게 만들어 점수를 올리는 것은 즉시 실패 사유다.** 지난 4건 전부 채점 로직 무변경으로
  점수를 올렸다 — 그게 기준선이다. `scripts/lib/oracle-score.mjs`·`crates/auto-hwp-cli/src/layout_score.rs`를
  건드리는 PR은 그 자체로 의심 대상이다.
- 표본 1~2건을 전체로 일반화하지 마라(`footnote` n=1 · `multicolumn` n=2는 그래서 판단 보류 중이다).

## 8. 규율 (역할과 무관하게 동일)

- **issue-first**: 구현·문서 변경의 첫 동작은 이슈다. `main` 직접 작업·직접 push 금지.
- **PR에서 멈춘다**: 사용자가 머지라고 하거나 변경이 사소(오타·주석·JOURNAL만)한 경우만 병합. 그 외엔 질문.
- 필수 checks: `issue-link` · `build-test` · `licenses`. 대화 해결 전 merge 금지.
- **체크포인트**: 작업 단위 완료·결정 확정마다 `docs/CURRENT_STATE.md`를 **보고보다 먼저** 갱신.
  종료 시 `docs/JOURNAL.md` 맨 위에 5줄 이내 append.
- 사용자 콘텐츠·민감 문서는 이슈/PR/CI 아티팩트에 올리지 않는다.
- UI·라우팅·클라이언트 상태를 바꿨으면 브라우저 실검수(스크린샷 한 장은 검수가 아니다).
- **못 고쳤으면 고쳤다고 하지 마라.** 기각 가설과 실마리를 남기는 것도 성공적 결과다 — #78이 그렇게
  남긴 기록이 #80을 풀었고, #80이 남긴 기록이 #82를 풀었다.
