## 1. 최종 종료 목표 (북극성 + 수용 기준)

**북극성(v2)**: 브라우저에서 업로드 → AI(챗)+수동 편집 → PDF export 프로덕션 + 양식 일괄 작성.
이번 배치의 "끝"은 아래 4개가 전부 참이 되는 것:

1. **충실도**: `.hwp` 게이트 3종 불변 + **셀 안 줄바꿈 게이트 신설·수치화**(현재 게이트는 본문 문단만
   잰다) + 한컴 저작 hwpx 표본 5종 오라클(세로 렌더 확인) 대비 ±1쪽.

   키보드/마우스로" 성립. e2e 그린(048 flaky 해소 포함).
3. **엔진 API**: 본문 캐럿의 정본 API(`body_text_hit`/`body_caret_rect`) 신설 — 현 SVG 정렬 레이어의

4. **릴리스**: npm **0.0.2** 발행(0.0.1 은 landscape 토큰 버그 포함 구버전) + 데모 재배포(라이브

## 3. 추가 리서치가 유익한 포인트 (구현 전 설계 조사 대상)

1. **셀 lineseg 존재 여부** — 한컴이 `<hp:lineseg>` 를 셀 내부 문단에도 저장하는가? 저장한다면 셀
   줄바꿈 게이트를 본문 게이트와 같은 방식으로 세울 수 있다(W1 의 선행 조사).
2. **실 한컴 검증 채널(U12)** — LibreOffice 오라클의 한계가 landscape 사건으로 실증됐다(토큰 하나로
   17↔25 반전). Windows VM + 한글 뷰어 자동화 / 한컴독스 API / 수동 QA 프로토콜 중 무엇이 현실적인지.
3. **문단을 넘는 범위 선택** — 현 범위는 한 문단 안(커밋 대상이 하나). 멀티 블록 커밋의 데이터 모델
   (트랜잭션 op? 블록별 분해?)은 설계 리서치 후 착수.
4. **i18n 전략** — SDK 한국어 하드코딩 6,154자, 메커니즘 0. 문자열 테이블 vs 슬롯 주입 vs "한국어
   고정 명시" 중 선택(EMBED-GUIDE 에 현 상태 명시는 W2 가 함).
5. **차트 파이프라인** — HWPX 차트는 별도 파트(`Chart/chartN.xml`, OOXML). 렌더러(`chart_svg`)가
   rhwp 안에 있어 hwp-hwpx 에서 못 닿는다. `.hwp` lift 차트도 직렬화에서 소실 중(기존 갭). 경로 설계 필요.
6. **073 LLM 보조** — 자유 텍스트 명단→구조화 파싱. 데모 AI 프록시(Cloudflare Worker, GLM 5.2)가
   살아 있어 재사용 가능. 프롬프트/파서/실패 UX 설계.
