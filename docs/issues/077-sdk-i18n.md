# 077 — SDK i18n: 한국어 기본값을 보존하는 호스트 주입형 문자열 계약

- 상태: **design-complete / implementation-open** (2026-07-28)
- 우선순위: **P1 (외부 SDK 채택성)**
- 영역: `packages/react`

## 실측

TypeScript AST로 production `.ts/.tsx`(테스트·주석 제외)를 세면 52파일 중 21파일에 한국어 UI literal이
있고, 한국어를 포함한 string-like node 337개·한글 음절 2,751자가 남아 있다. `HwpWorkspace`와
`ChatPanel` 두 파일이 한글 음절의 약 72%를 차지한다. 기존 “6,154자”는 테스트/주석까지 포함한 거친
수치라 구현 규모 추정에는 쓰지 않는다.

## 결정

- 외부 런타임 의존성을 추가하지 않고 `WorkspaceMessages` 타입과 `koKR` 기본 catalog를 둔다.
- `HwpWorkspaceProps.messages?: DeepPartial<WorkspaceMessages>`를 additive로 추가한다.
- 내부 React context에서 기본값과 호스트 override를 깊게 병합한다. 문자열 prop-drilling은 하지 않는다.
- 동적 문구는 `"prefix" + n` 조합 대신 타입이 있는 함수 메시지로 둔다.
- 독립 export된 component도 provider가 없으면 한국어 기본값으로 동작한다.
- 엔진의 자유 형식 오류는 이 단계에서 억지 번역하지 않는다. 후속으로 stable error code를 추가하고,
  알 수 없는 코드는 원문을 fallback으로 노출한다.

## 드리프트 방지

- production source의 새 bare 한국어 literal을 AST 검사로 차단한다.
- 문서 내용, 글꼴 이름, 테스트 fixture 등 번역 대상이 아닌 값은 좁은 allowlist로 관리한다.
- catalog key 누락은 TypeScript에서 실패한다.

## 수용 기준

- [ ] messages prop을 주지 않은 기존 한국어 DOM/snapshot이 바이트 수준으로 유지된다.
- [ ] `enUS` smoke에서 업로드→선택→편집→undo→PDF/HWPX export의 핵심 chrome이 영어로 보인다.
- [ ] 숫자·단축키·기술명은 catalog가 아닌 구조화된 interpolation으로 유지된다.
- [ ] 호스트가 key 일부만 override해도 나머지는 `koKR`로 안전하게 fallback한다.
- [ ] 외부 i18n 패키지와 React 외 런타임 의존성은 0이다.
