# 083 — README 비주얼 개편: 스크린샷·GIF 베이스 재구성

- 상태: **기획 확정 · 미착수** (2026-08-10)
- 우선순위: P2 (전환율 축 — 코드보다 눈이 먼저 믿게 한다)
- 배경: claw-hwp처럼 시각 자료 중심의 다채로운 README로. 단 **2026-08-04의 README 압축 결정
  ("핵심·바로 사용 중심, 현학 금지")을 유지한다** — 글을 늘리는 게 아니라 글 자리를 이미지로 바꾼다.

## 원칙

1. 이미지가 주장하고 텍스트는 캡션 1줄 — 섹션당 본문 3줄 상한(기존 압축 규율 유지).
2. **모든 샷은 스크립트로 재촬영 가능해야 한다** — 손 캡처 금지. 릴리스마다 UI가 변하므로
   결정적 재촬영 스크립트가 없으면 스크린샷은 즉시 부채가 된다.
3. npm/GitHub 겸용: npm 레지스트리는 상대 경로 이미지를 못 그린다 — **절대 URL**
   (`https://autohwp.com/readme/...` 권장 — 도메인이 곧 브랜드; raw.githubusercontent 폴백).
4. 용량 규율: 정지 샷 webp ≤150KB, GIF는 총 2개 이하·각 ≤2.5MB(README 로드 체감 상한).
   저장은 `apps/hwp-lab/public/readme/`(사이트가 곧 CDN) + 레포에는 촬영 스크립트만 필수.

## 샷 리스트 (7컷 — 촬영 대상은 전부 현재 프로덕션 기능)

| # | 샷 | 형식 | 내용 |
|---|---|---|---|
| 1 | 히어로 | 기존 배너 유지 | 캘리그래피 워드마크(이미 적용) |
| 2 | **코어 퍼널 GIF** | GIF ~15s | 업로드 → 바이브 챗 표 채움 → 고스트 프리뷰 → 적용 → PDF 미리보기. 한 컷이 제품 전체를 말한다 |
| 3 | 3-면 뷰 | webp | 원본·자체 렌더·HTML — 충실도 한눈 대조 |
| 4 | 정밀 선택+프리뷰 | webp | 행 머리+앵커 칩+고스트 오버레이(2026-08-10 신기능 — 최신임을 보여주는 컷) |
| 5 | PDF 미리보기 모달 | webp | 화면=PDF 폰트 일치 증명 컷(같은 문단 나란히) |
| 6 | 벌크 깔때기 | GIF ~8s 또는 webp | 명단 → N부 zip |
| 7 | 임베드 코드+결과 | webp 합성 | `<HwpWorkspace/>` 코드 5줄과 렌더 결과 나란히 — SDK 소비자용 |

## 실행 계획

1. `scripts/shoot-readme.mjs` (playwright): 고정 뷰포트 1440×900·라이트 테마·sample-8p·
   각 샷의 상태를 e2e 헬퍼 재사용으로 재현 → `--update` 플래그로만 덮어쓰기. GIF는 playwright
   video → ffmpeg palettegen 변환(기존 gif 도구 재사용 가능하면 그것).
2. README.md / README.en.md 재배치: 배너 → 배지 → **GIF(#2)** → 30초 시작(기존 압축 유지) →
   기능 그리드(샷 3·4·5·6을 2×2 표, 캡션 1줄) → SDK(#7) → 벤치 수치 링크 → 이하 기존 링크 허브.
3. 산출물을 `apps/hwp-lab/public/readme/`에 넣고 Vercel 배포로 서빙 → README에는 autohwp.com 절대 URL.
4. 가드: 촬영 스크립트를 verify에 넣지 않는다(느림) — 대신 릴리스 체크리스트(CHANGELOG 절차)에
   "UI 변경 릴리스 시 shoot-readme 재실행" 1줄.

## 함정

- GIF 자동재생은 GitHub에서만 — npm은 첫 프레임 정지. #2 GIF 첫 프레임을 "완성 화면"으로 잡을 것.
- 다크/라이트: 샷은 라이트 고정(디폴트 테마). GitHub 다크 모드에서 흰 배경 샷이 뜨는 문제는
  `<picture prefers-color-scheme>`까지 가지 말고 얇은 테두리로 해결(과설계 금지).
- 문서 내 실데이터 금지 — sample-8p(공개 양식)만 사용.
