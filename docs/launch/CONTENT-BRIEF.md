# 오픈소스 런칭 콘텐츠 브리프

## 한 문장

**AI가 한글을 이해하고, 수정하고, 마침내 정복할 수 있는 미래를 위해 — 한글 문서를 남의 서비스에
맡기지 않고 브라우저·내 서버·내 에이전트에서 같은 Rust 코어로 열고, 고치고, 검토하고, 다시
내보내는 오픈소스 문서 엔진과 편집기 SDK.**

AI가 주인공이 아니다. 주인공은 하나의 문서 모델과 로컬 코어이고, AI는 사용자가 원할 때 그 위에
연결하는 선택적 조작자다.

## 메시지 우선순위

1. **로컬 우선** — 문서 파싱·조판·렌더·편집·내보내기는 브라우저 또는 사용자 인프라에서 실행된다.
2. **코어 하나, 셸 셋** — React 웹, 네이티브/서비스, wasm이 같은 IR·Intent·검증 규율을 공유한다.
3. **에이전트가 안전하게 고친다** — 자유 텍스트가 아니라 타입이 붙은 Intent를 제안하고, 사람이
   프리뷰한 뒤 승인하며, 한 단위로 되돌린다.
4. **주장을 재현할 수 있다** — 페이지 수·줄바꿈·round-trip을 공개 픽스처와 커맨드로 증명한다.
5. **한계를 먼저 말한다** — 폰트 정책, 암호 문서, PDF 수식/차트, HWP/HWPX 저장 범위를 숨기지 않는다.
6. **가벼운 집단지성** — 브라우저에서 자기 문서를 열어 레이아웃 차이를 보고, 문서 내용 없이 GitHub
   이슈로 구조와 쪽수만 제보하는 것부터 기여다.

## 게시물 세트

### 1. 한국어 런칭 본문

문제 장면(사업계획서가 서비스에 업로드됨) → 로컬 코어 → 15초 코어 퍼널 → 에이전트 복사 프롬프트 →
공개 벤치 → 설치 60초 → 한계·기여 요청 순서. GeekNews/블로그 공용 장문 정본으로 쓴다.

### 2. 영어 요약

`Local-first HWP/HWPX engine and React editor SDK`를 첫 문장으로 한다. 한국 시장 설명보다
browser wasm, typed Intent, BYOK, reproducible benchmark를 앞세운다.

### 3. 에이전트 연동 레시피

빈 Vite 또는 Next 앱에서 `docs/launch/AGENT-PROMPT.md`를 에이전트에 전달하고, 생성된 diff와 실제
smoke 결과를 함께 싣는다. 사람이 손으로 고친 숨은 단계가 없어야 한다.

### 4. 신뢰 게시물

왜 SVG를 sanitize하는지, 파일과 AI 문맥이 어디서 분기되는지, HWPUNIT/px와 round-trip 게이트가 왜
필요한지를 설명한다. 보안 정책과 공개 벤치로 연결한다.
