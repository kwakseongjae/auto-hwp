# Support

auto-hwp is an open-source project, not a hosted document-processing service. The public demo is a bounded trial surface;
it does not create an uptime, data-recovery, or compatibility SLA.

## Choose the right channel

| Need | Where to go |
|---|---|
| Reproducible bug in the latest stable | [Bug report](https://github.com/kwakseongjae/auto-hwp/issues/new?template=bug_report.yml) |
| Proposed capability or API change | [Feature request](https://github.com/kwakseongjae/auto-hwp/issues/new?template=feature_request.yml) |
| Layout mismatch with a redistributable or synthetic file | Use the layout-gap issue template |
| Security or private-data exposure | [Private vulnerability report](https://github.com/kwakseongjae/auto-hwp/security/advisories/new) |
| Integration guidance | Read [llms.txt](./llms.txt), then the [LLM](./docs/LLM-GUIDE.md) or [embed guide](./docs/EMBED-GUIDE.md) |

Before filing, reproduce on the latest public stable, search existing issues, and run the smallest relevant verification.
Post commands and structural facts rather than document contents. Do not attach private government, employment, financial,
health, or customer documents; reduce the problem to a synthetic fixture first.

## What maintainers can provide

Maintainers can clarify documented contracts, triage reproducible defects, and review scoped contributions. They generally
cannot debug an undisclosed proprietary document, operate your deployment, choose an LLM vendor for you, or guarantee
pixel-identical output for fonts and objects outside the published fidelity contract.

Responses are best effort. A clear minimal reproduction and a proposed regression test are the fastest path to a fix.
